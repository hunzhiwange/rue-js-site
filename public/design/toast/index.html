Toast 轻提示

Toast 根容器负责 placement、stack 和 inset。根容器仍然负责 placement、stack 和 inset， 但单条提示现在可以直接用Toast.Item写出接近 message 的反馈体验：类型、标题、说明、 操作区、关闭按钮、自动关闭与悬停暂停都已经补充；现在还可以像常见 message API 一样通过Toast.useMessage()拿到messageApi和contextHolder， 在业务按钮、异步流程和页面局部容器里直接按 key 推送、更新和销毁消息；默认会弹到全局页面层， 只有显式传 getContainer={false}时才会留在当前 box 里，同时仍然使用 Rue 自己更轻、更靠近页面内容的视觉语气。

何时使用

  • 需要在页面局部提供轻量反馈，但不想上升成全局通知系统。
  • 希望像 message 一样直接描述成功、失败、加载、警告这些状态，又想保持更贴近 Rue 的视觉风格。
  • 希望在事件处理函数里直接触发反馈，而不是先把消息数组提升到页面状态。
  • 既要支持基础的 alert 容器写法，也想在业务里直接拿到可关闭、可自动关闭的单条提示能力。

# Controlled and auto close

受控关闭适合和外部状态联动；自动关闭则提供了 message 常用的短时反馈体验，并支持 hover 暂停。

受控提示使用固定 key 反复显示或销毁；自动关闭提示每次生成新 key，悬停时会暂停倒计时。

# Toast.useMessage

参考常见 message hook 的形态：把 contextHolder 放进页面即可，真正的消息默认弹到全局页面层；如果你要留在当前 box，再显式传 getContainer={false}。

API

Toast.useMessage(options)

属性说明类型默认值
placement / inset / gap / zIndex复用 Toast 根容器的定位能力；默认消息层会挂到全局页面层，而不是被当前 box 裁住。ToastProps 子集placement = 'top'
getContainer控制消息挂载位置；默认挂到 document.body，传 false 时退回到 contextHolder 所在的局部 box。string | HTMLElement | (() => HTMLElement) | falsedocument.body
maxCount限制同时显示的消息数量；超过时会自动挤掉最早的一条。number-
duration给 hook 创建出来的消息设定默认自动关闭时长，单条消息可覆盖。number | null3
variant / closable / pauseOnHover / showIcon / type为整个 message 通道设定单条提示的默认外观和行为。ToastItemProps 子集-

返回值固定为[messageApi, contextHolder]。为了保持这类 hook 的用法习惯，contextHolder仍然建议真实渲染到页面里；默认情况下它主要跟随当前组件生命周期，真正的消息层会挂到document.body，传getContainer={false}时才会回到 holder 内。

messageApi

属性说明类型默认值
open(config)创建一条消息；返回关闭函数，适合临时保存句柄。(config: ToastMessageConfig) => () => void-
success / info / warning / error带语义类型的快捷方法，等价于 open({ type, ...config })。(config) => () => void-
loading(config)加载态快捷方法，默认会把 duration 设为 0，便于后续按 key 更新。(config) => () => void-
destroy(key?)销毁指定 key 的消息；不传 key 时清空当前 holder 里的全部消息。(key?: string | number) => void-

ToastMessageConfig

属性说明类型默认值

contentmessage 风格的主内容；未传 children 时会直接渲染在正文区域。any-
children需要 richer JSX 时可直接传 children，优先级高于 content。any-
其余字段type、duration、action、closable、variant、icon、onClose 等字段复用 Toast.Item。ToastItemProps 子集-
