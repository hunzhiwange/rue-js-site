Mockup Window 窗口外框

MockupWindow 可以使用 Rue 基础的静态窗口外壳视觉，同时补了一层更顺手的结构化 API。 既可以继续直接写 children，也可以用 title、toolbar、actions 快速搭一个带头部和底部操作区的展示窗口。

何时使用

  • 需要模拟一个系统窗口、面板或预览壳层，用来承载展示内容。
  • 希望使用 Rue 当前 mockup-window 视觉，但不想每次都手写头部、内容区和底部操作区。
  • 需要同时兼顾推荐用法和完全手动拼装的低层布局能力。

API

MockupWindow 同时支持“基础的 children 直出模式”和“新的结构化窗口模式”。

属性说明类型默认值
actions底部操作区；传入后自动渲染带分隔线的底栏any-
actionsClassName底部操作区 classNamestring-
background为根节点追加 bg-base-100booleanfalse
bordered为根节点追加 border border-base-300booleanfalse
bodyClassName内容区 className；启用语义模式时作用在自动生成的 Body 上string-
children窗口内容；未启用增强结构时会原样透传any-
className根节点 classNamestring-
description头部辅助说明文案any-
headerClassName头部区域 classNamestring-
padding自动生成 Body 的内边距'none' | 'sm' | 'md' | 'lg''md'
title头部标题；与 description / toolbar 组合后启用结构化窗口any-
toolbar头部右侧工具区，适合按钮、状态和筛选器any-

复合子组件

MockupWindow.Header：标准头部，支持title、description和extra
MockupWindow.Toolbar：头部工具区包装器，默认横向排列
MockupWindow.Body：内容区，可选padding
MockupWindow.Actions：底部操作区，默认右对齐并带分隔线

FAQ

什么时候用根组件属性，什么时候用复合子组件？

如果只是常见的标题栏 + 内容区 + 按钮栏，优先直接使用根组件的title、toolbar和actions。当你需要完全自定义头部排版，再切换到 MockupWindow.Header这类低层拼装方式。

padding 应该怎么理解？

padding只作用于结构化模式下自动生成的Body。如果你已经手动使用 MockupWindow.Body或自己管理内容布局，直接在内容节点上写 className 会更直接。
